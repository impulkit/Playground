What is open-source software?

In 1991 a Finnish student posted online that his new operating system was "just a hobby, won't be big and professional". Today it runs most of the world's servers and every Android phone.

The short answer

Every app or program starts as source code: instructions written by people in a programming language. Most companies keep their source code secret. Open-source software is different. Its code is published for anyone to read, use, change and share, usually for free.

That means a student in Kochi, a company in California and a volunteer in Brazil can all improve the same program. Some of the most important software on Earth is open source, including Linux, which runs most web servers, and the core of Android, which runs on billions of phones.

Surprising but true

Since 2017, every one of the world's 500 fastest supercomputers has run Linux, the free operating system started by that student.

A recipe anyone can change

Think of source code as a recipe. With ordinary software, you can eat the cake but never see the recipe. With open source, the recipe is printed for everyone. You can bake it, add cardamom, share your version with friends, or point out that step five burns the bottom.

The rules for sharing are set out in a licence. Some licences say that if you share a changed version, you must also share your changes openly. Others let you use the code almost any way you like.

A free system and a hobby project

In 1983 an American programmer, Richard Stallman, started a project called GNU to build a complete operating system that anyone could use and share freely. He believed people should be free to study and change the software on their own computers.

By 1991 GNU had many parts but still lacked its central piece, the kernel. That year Linus Torvalds, a 21-year-old student in Helsinki, posted online that he was writing one. It was "just a hobby", he wrote, and "won't be big and professional". Thousands of volunteers joined in. Combined with GNU tools, his Linux kernel became a complete free system.

Who uses it

Today Linux runs most of the computers behind websites, much of the cloud, and every one of the world's 500 fastest supercomputers. Android, the most common phone system, is built on Linux. The Firefox browser, the Python programming language and the software behind Wikipedia are open source too.

Governments use it as well. In 2015 the Government of India published a policy asking its departments to prefer open-source software where possible, partly to save money and avoid being locked in to one company.

Why give it away?

It can seem odd that people write software and give it away. Some do it to learn, or for fun, or because they believe knowledge should be shared, the way public libraries share books. Many companies pay their staff to work on open source because they rely on it and it's cheaper to improve shared code than to build everything alone. Others earn money by selling support, hosting or extra features.

Working openly also looks good. Many programmers get hired after employers see the code they have shared publicly.

When it goes wrong

Openness has a weak spot. Huge companies sometimes depend on small projects run by a few unpaid volunteers. In 2014 a bug called Heartbleed was found in OpenSSL, software that helps secure websites. It had gone unnoticed for about two years. In 2021 another flaw, in a free tool called Log4j, put millions of systems at risk.

Both were found and fixed because the code was open for anyone to inspect. Since then, companies and governments have started paying to support the volunteers who keep the internet's hidden foundations standing.

Myth or fact?

Myth: Open-source software is less safe because anyone can see how it works.

Truth: Being open means many people can look for and fix mistakes, and a lot of the world's most trusted security software is open source. But openness only helps if people actually check the code, and some popular projects have been short of helpers.

Try this

Write out the steps for making a simple snack, like a sandwich or bhel, and share your "source code" with a friend. Ask them to improve one step and send it back with a note of what they changed. You have just run a tiny open-source project.
